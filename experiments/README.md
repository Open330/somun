# 초안 품질 실험

외부 실험 플랫폼·운영 DB 없이 실행하는 초안 단계 평가 도구다. 고정된 **요약 이후의 사실 입력 → 초안 생성 → 규칙 검사 → 사람 검토**를 평가한다. 수집·다이제스트·판단·발행까지의 종단간 제품 평가는 아직 포함하지 않는다. 현재는 생산용 draftPrompt를 사용하되 개인 설정·프로필·학습 예시는 불러오지 않고 고정 사실과 변형별 편집 지시를 평가한다.

## 바로 실행

Node 22, `npm ci` 후 프로젝트 루트에서:

```sh
# 기본: 네트워크·모델 호출 없이 6개 채널의 정상/오류 표본 12개 평가
npm run experiment

# 이전 실제 생성에서 발견했던 문제를 재현하는 4개 결과 평가
npm run experiment -- run --config experiments/historical.json

# 실제 생성은 명시적으로 선택. 이 예시는 2개 결과를 생성한다.
npm run experiment -- run --config experiments/live.json --live --max-calls 2
```

`replay.json`은 검사기 검증용 합성 표본이다. reference는 자동 규칙을 통과하는 최소 글이며 사람이 선호하는 모범 답안이라는 뜻이 아니다. `historical.json`은 앞선 실제 생성 결과를 고정한 회귀 사례다. 여기에 포함된 문제를 바탕으로 기대 조건을 만들었으므로 독립적인 미공개 평가 세트가 아니다.

기본은 항상 replay이며 `--live` 없이는 모델을 호출하지 않는다. live는 명시적 provider/model과 충분한 `--max-calls`가 있어야 시작한다. 이 상한은 생성 작업 수이며 SDK 내부 재시도를 포함한 HTTP 요청 수나 비용 상한은 아니다. 한 결과당 타임아웃은 90초다. Gemini 모델 자동 대체는 사용하지 않고 실제 응답 모델도 별도로 기록한다. 모델명은 사용 가능한 모델로 설정한다.

키는 환경변수에서만 읽는다: `GEMINI_API_KEY` 또는 기존 `GEMINI_API_KEYS`의 첫 무료 키, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`. 키 자체는 설정 파일이나 결과에 기록하지 않는다. provider 오류 원문도 저장하지 않으며 HTTP 상태와 타임아웃 여부만 진단에 남긴다. 모델 실행은 비결정적이며 동일 설정이 동일 문장을 보장하지 않는다. 원문 입력과 생성 출력은 결과에 포함되므로 공개/합성 자료부터 사용한다.

## 결과 파일

실행마다 새 `experiments/runs/<시간>-<식별자>/`를 만든다. `--out /원하는/새/경로`도 가능하며 기존 경로는 덮어쓰지 않는다. runs는 Git에서 제외된다.

- `report.json`: 입력·사례별 기대 조건, 요청/실제 모델, 출력, 프롬프트와 해시, 검사 결과, 지연, 제공되는 경우 토큰 사용량. 완료한 결과마다 기록해 중단 시 손실을 줄인다.
- `config.json`: 실험 설정 스냅샷.
- `evaluator-sources.json`: 평가 코드 스냅샷. dirty 작업 트리에서도 사용한 검사 코드를 확인한다.
- `summary.md`: 변형별 오류와 자동 검사 통과 수. 실패 결과도 분모에 남는다.
- `review.json`: 모델·변형 이름과 자동 점수를 숨기고 순서를 섞은 사람 평가 양식.

재생 결과의 소요 시간은 `n/a`다. replay에 기록된 프롬프트는 현재 코드가 구성하는 프롬프트이며 저장된 과거 출력을 실제로 만든 프롬프트라는 뜻이 아니다. 입력·출력 스냅샷을 재검사하는 용도다. 중단된 실행은 부분 결과로 남으며 자동 재개는 지원하지 않는다.

## 변형과 반복

설정의 `variants`에 고유한 id와 provider/model, 선택적인 instruction을 추가한다. 비교하려는 요인 하나씩 변경한다. instruction은 현재 생산용 draftPrompt의 편집 지시 필드에 들어간다. 전체 프롬프트 코드 변경은 변경 전후 별도 실행으로 비교한다.

`ab.json`은 기본 지시와 간결한 지시를 같은 모델에서 2회씩 비교하는 예시다. `npm run experiment -- run --config experiments/ab.json --live --max-calls 8`로 8개 결과를 만들 수 있다.

`repeats`는 live에서 1~5이며 사례 × 변형 × 반복만큼 생성한다. 사례/반복별로 변형을 교차 실행하고 짝수 반복에는 순서를 뒤집는다. 비용 폭주를 줄이기 위해 실행당 최대 100개 결과를 허용한다. replay 반복은 1만 허용한다. 복사한 출력을 독립 표본처럼 계산하지 않는다. 실행 시간이 길거나 자료가 크면 데이터셋을 나눈다.

초기 `cases.json`은 6개 채널과 한국어/영어를 포함한다. 기대 조건 `required`/`forbidden`은 대소문자를 무시하는 문자열 검사다. 의미적 사실 판정이나 포괄적인 환각 탐지기가 아니다. 근거 없는 수치, 한계, 소유·출시 표현 같은 알려진 회귀를 잡는 데 사용한다. 언어 자연스러움, 링크가 실제로 유효한지, 근거 숫자의 의미가 같은지는 별도 검토가 필요하다.

## 사람 평가

실험 실행이 끝난 후 평가자에게 **review.json만** 전달한다. report/config에는 변형 정보가 있으므로 같이 전달하면 가림 효과가 없다. 작성된 답변 자체에서 설정을 추측할 가능성도 있다. 같은 양식의 사본을 평가자별로 보관하고 개별 집계한다. 평가자 간 합의도나 다중 평가자 통합은 아직 제공하지 않는다.

`ratings`, `publishable`, `editSeconds`, `notes`만 수정한다. 원문과 초안은 그대로 두고 수정 제안은 notes에 남긴다.

| 항목 | 1 | 3 | 5 |
|---|---|---|---|
| grounding | 중요한 사실을 지어내거나 왜곡 | 출처 대조·사실 수정 필요 | 검토한 주장 모두 근거에 충실 |
| clarity | 이해하기 어려움 | 문장/구조 수정 필요 | 간결하고 이해하기 쉬움 |
| voice | 채널·언어에 부자연스러움 | 몇 군데 수정 필요 | 의도한 채널과 어조에 자연스러움 |

2와 4는 중간 수준이다. `publishable`은 사실·문장 검토 후 현재 초안을 그대로 게시할 의향이다. `editSeconds`는 게시 준비까지 실제로 검토/수정한 시간이고 미측정은 null이다. 0은 실제 측정값 0일 때만 쓴다. 필수 점수와 publishable 중 하나라도 null이면 미평가로 남는다. 미평가를 0점/실패로 합산하지 않는다.

```sh
npm run experiment -- review --run experiments/runs/RUN/report.json --reviews experiments/runs/RUN/review.json
```

세 점수를 단일 총점으로 합치지 않는다. 사실성 결함을 문장 점수로 상쇄하지 않기 위해서다. 시간 절약을 주장하려면 같은 난도의 글을 직접 작성한 대조군 시간도 별도로 측정해야 한다.

## 회귀 비교

```sh
npm run experiment -- compare --before experiments/runs/BEFORE/report.json --after experiments/runs/AFTER/report.json
```

같은 사례·기대 조건·변형 ID·반복 번호가 모두 짝지어지는 완료 실행만 비교한다. 자동 검사 악화 또는 검사 항목 제거가 있으면 종료 코드 1, 비교 불가능한 입력도 실패 종료한다. 추가/제거된 검사와 평가 코드 변경 여부를 보여준다. 이 명령은 모델 승자나 통계적 유의성을 판정하지 않는다. replay와 live가 섞이면 결과의 mode를 확인해야 한다.

`npm test`에는 실험기 자체 회귀 검사가 포함된다. 현재처럼 이미 본 소수 사례의 성공률로 일반 품질을 주장하지 말고, 발견한 실패를 회귀 세트에 추가하는 한편 별도 보류 평가 세트를 늘려간다. 자동 모델 심사, 실사용 과업 성공률, 수집부터 발행까지의 실험은 후속 범위다.

## 초기 구현 검증

전체 25개 테스트 파일의 126개 테스트가 통과했다. 합성 정상 표본 6/6 통과, 오류 표본 6/6 탐지, 과거 실생성 표본 수정 전 0/2·수정 후 2/2 통과를 확인했다. 동일 실행 비교와 미평가 사람 평가 양식 집계도 CLI로 실행했다.

실제 모델 실험도 두 번 실행했으며 각 실행은 2건 중 1건 성공·1건 실패였다. 후속 실행에서는 실패가 90초 타임아웃임을 기록했다. 이를 정상 품질 점수로 숨기지 않고 생성 오류로 별도 표시한다. 사람 평가 점수는 아직 입력하지 않았다. [검증 요약](../docs/generation/experiment-validation.json)에 수치와 실제 요청/응답 모델을 기록했다.

## 변경 보존·한국어 후속 실험

`coverage.json`은 단순 간결화와 모든 변경 보존 지시를 비교한다. `coverage-production.json`은 기본 프롬프트의 변경 확인 목록을, `coverage-korean.json`은 한국어 용어 지시를 포함한 현재 코드를 확인한다. 모델 호출 수는 각각 8·4·2건이다. 실행 당시 프롬프트는 각 report.json에 보존되므로 이후 코드로 재실행한 결과와 구분한다.

사례는 기존 파일을 덮어쓰지 않고 `coverage-cases.json`, `coverage-cases-v2.json`, `coverage-cases-v3.json`으로 남겼다. v2부터 `requiredAny`로 개념별 동의어를 허용한다. 예를 들어 `{"id":"preload","phrases":["preload","미리 로드","사전 로드","프리로드"]}`는 어느 표현이든 하나가 있으면 통과한다. v3는 정상 음역 ‘프리로드’를 추가했다. 이 검사는 여전히 문자열 기반이며 의미 정확성을 보장하지 않는다. requiredAny가 없는 과거 보고서는 기존 데이터 해시가 유지된다.

[후속 결과](../docs/experiments/2026-09-22/coverage/REPORT.md)는 원래 점수와 새 기준의 사후 재평가를 구분한다. 평가 기준을 고친 뒤 과거 실패를 숨기거나 새 생성 성공으로 계산하지 않는다.
