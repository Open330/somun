# 게시 가능한 초안 품질 보완

## 발견한 문제와 변경

1. 프롬프트는 근거가 없는 숫자·한계를 생략하도록 했지만 lint는 그것들이 없다고 경고했다. 숫자·한계 존재를 의무화하는 검사를 제거했다. 내용이 없는 형식 채우기를 유도하지 않는다.
2. 사용자 수정 저장 시 생성 단계의 한계 검사가 빠졌다. 두 경로가 같은 프로젝트 프로필·글감 근거로 검사하도록 통일했다.
3. 근거에 없는 수치가 있어도 형식 검사를 통과할 수 있었다. 제공된 사실 블록과 수치를 대조해 확인 대상을 표시한다. URL 숫자와 목록 번호는 제외하고, 버전의 v 접두사와 천 단위 쉼표는 정규화한다. 퍼센트와 단순 개수는 구별한다.
4. 경고 설명이 배지의 hover 정보에 머물렀다. 초안 위에 ‘초안에서 확인할 부분’을 펼쳐 원문 확인이 필요한 이유를 읽을 수 있게 했다. 표시 결과는 저장된 초안 기준이며 저장 후 다시 검사한다고 안내한다.
5. Show HN/GN 형식이 근거 없는 문제 상황·비교·한계를 유도했다. 근거 없는 섹션을 생략하고, 저장소 연결만으로 작성자가 소유자·개발자·출시자라고 추정하지 않도록 지침을 보완했다.
6. forks를 모를 때 Facts에 0으로 표시하던 부분을 생략하도록 수정했다.

## 검증

- 전체 24개 파일 119개 테스트 통과. 6개 채널 모두 숫자·한계를 강제하지 않는지, 생성과 수정 저장의 경고가 유지되는지 검사한다.
- 린트·타입 검사·프로덕션 빌드 통과. 프롬프트 후속 보완 후 관련 회귀 검사 44개와 빌드도 다시 통과했다.
- 고정된 공개 Vite 릴리스 자료를 사용해 Show HN 영어와 Show GN 한국어를 실제 모델로 생성했다. 운영 DB나 외부 게시에는 반영하지 않았다.
- 첫 생성은 자동 경고가 없었지만, 사람이 읽어보니 출처에 없는 대규모 코드베이스 병목, 작성자 출시 표현, 변경 사항을 도구 비교로 분류한 문제가 있었다. [첫 결과](generation/quality-review-before.json)를 보존하고 지침을 수정해 [재생성 결과](generation/quality-review.json)를 별도로 기록했다.

## 재생성 관찰

Show HN(약 12.9초)은 출처에 없는 대규모 코드베이스 병목 설명을 제거하고 네 가지 변경을 직접 설명했다. Show GN(약 37.9초)은 “출시했습니다” 대신 “변경 사항입니다”로 시작했고, 근거 없는 도구 비교 섹션과 한계를 넣지 않았다. 두 결과 모두 현재 자동 규칙을 통과했다. 이는 이 표본에 대한 관찰이며 매번 같은 결과를 보장하지 않는다.

## 검사 범위

수치 대조는 자동 사실 판정이 아니다. 같은 숫자가 근거에 있어도 문맥·단위·인과관계가 다를 수 있다. 번역 오류, 수치 없는 과장, 요약 단계의 오류는 별도 원문 검토가 필요하다. 검사에 쓰는 근거는 현재 글감·프로필이며 과거 생성 시점의 불변 스냅샷은 아니다.

이번 결과는 채널 2개·자료 1개의 표본이다. 모든 모델과 채널의 품질이나 실제 사용자 시간 절약을 검증한 것은 아니다. 기존 X·Threads 결과와 함께 사례를 늘리고, 실사용에서 검토 시간·사실 수정·게시 가능 여부를 평가해야 한다. GitHub 최초 연결 권한 정책과 운영 배포는 이전 보고서의 미완료 항목으로 남아 있다.

## 배포 전 후속 보완 — 2026-10-06

아래는 별도 `fix/pre-release-quality` worktree에서 수행한 후속 작업이다. 앞 절의 테스트 수와 미완료 권한 정책은 당시 기록이며, 현재 구현 상태와 구분한다.

### 공유 모델 사용량 보호

- 기본값은 계정별 UTC 하루 모델 실행 50회와 대기·실행 중인 서버 큐 작업 20개다. `SOMUN_SHARED_MODEL_DAILY_LIMIT`, `SOMUN_SHARED_MODEL_PENDING_LIMIT`로 조정할 수 있다.
- 프로필·요약·판단·초안·자동 보정은 실행 전에 DB에 사용량을 예약한다. 실패도 횟수에 포함하고, 제공자 재시도는 같은 실행으로 계산한다. 계정별 횟수는 서버 재시작과 여러 DB 연결 사이에 유지된다. 개인 API 키·로컬 워커에는 공유 모델 제한을 적용하지 않는다.
- 중복 요청은 기존 작업에 합친 뒤 큐 용량을 검사한다. 초과 요청은 `429`, `Retry-After`, 재시도 시각을 반환한다. 일괄 요청은 초과하면 전체 롤백한다.
- 완료한 단계의 자리를 먼저 비우고 후속 작업을 접수한다. 한도가 후속 단계를 막아도 생성된 요약·초안은 보존하고, 막힌 단계에 다시 시도할 수 있는 이유를 남긴다. 한도 때문에 실행하지 않은 모델 요청은 제공자 사용량으로 기록하지 않는다. 초안 수정 저장·복사는 계속 사용할 수 있다.
- 작업 상태 화면에는 현재 계정의 실행 횟수와 초기화 시각을 표시한다. 다른 계정이나 서버 키 식별자는 노출하지 않는다. 한도에 도달했을 때 모델 상태를 이용 가능으로 표시하지 않는다.

### 로그인과 GitHub 연결

- 최초 설치 연결 권한은 이미 일회용 state·GitHub OAuth 사용자 확인·설치자 일치로 보완돼 있다. 이전 문서의 정책 미완료 판정을 최신 상태로 정정했다.
- 콜백 화면이 일회용 code/state를 effect 재실행으로 중복 제출하지 않도록 같은 Promise를 공유한다. 주소에서 인증 code/state를 지우고, 실패 후 로그인 화면 또는 연결 관리로 돌아가는 경로를 제공한다. StrictMode 재실행·성공·실패 복구를 회귀 테스트했다.
- 실제 운영 OAuth 진입 요청은 GitHub 인증 페이지로 `302` 이동했다. 실제 GitHub App API 응답은 `200`이며 OAuth 자격 증명과 필요한 읽기 권한이 구성돼 있다. 비밀값은 검증 결과에 저장하지 않았다.
- 운영 인증 API의 `/auth/exchange`, `/auth/token`, `/auth/external/refresh` 사전 요청은 `204`였고, `https://somun.jiun.dev` 출처와 credentials를 허용했다. 설정 확인이며 실제 로그인 완료 검증은 아니다.
- **실계정 로그인·설치 왕복은 아직 완료하지 않았다.** 별도 Chrome 검증창은 GitHub 로그인을 기다리고 있다. 자동 테스트나 설정 확인을 실제 OAuth 사용자 동의 왕복으로 집계하지 않는다.

### 생성 품질과 표현

- 소개글 입력에서 커밋 수·릴리스 수·최초 릴리스 날짜를 제외하고, 공개 프로젝트 이름을 명시한다. 저장소 활동을 제품 성숙도로 바꾸거나 작성자 역할을 추정하지 않도록 지침을 보완했다.
- 선택된 직접 개발·출시 표현은 `작성자 역할 확인` 경고를 표시하고 자동 보정에도 전달한다. 경고를 진위 판정으로 취급하지 않는다. 경고가 남은 표현을 문체 학습 예시로 넣지 않는다.
- Blog는 본문 대신 줄별 개요와 실제 독자 질문을 요청하고, 개요가 아닌 문단·질문 자리표시자는 경고한다. 제목 후보·절 번호는 주장 수치에서 제외하되 같은 줄의 실제 숫자 주장은 계속 검사한다.
- Show HN은 릴리스 항목만 보고 설계 구조나 동작 원리를 추정해 문단을 채우지 않도록 변경했다.
- 6개 채널의 지원 언어 조합에서 소개글·업데이트 총 20개 사례를 평가했다. 기본 모델과 대체 모델의 직접 호출 실패를 보존하고, 실제 앱의 큐·무료 키 풀·한 번의 자동 보정 경로로 20개를 생성했다. 그 뒤 Blog·Show HN 6개를 재검증했다. 운영 데이터와 외부 게시에는 반영하지 않았다.
- [전체 생성 결과와 원문 대조 기록](generation/pre-release-20261006.json)은 사실·문장·채널 형식을 나눠 검토한다. 검토자는 Codex이며 실제 사용자 평가가 아니다. 원자료가 복잡한 기술 동작을 설명하지 못하면 번역을 게시 전에 대조해야 한다. 자동 보정 후에도 영어 Blog 소개글의 개요 경고가 남았고, 과도한 표현·어색한 문장에는 수동 수정이 필요한 표본이 있다.
- 실제 Vite 구현에서는 이미 처리된 의존성의 빈 결과를 `allSettled` 입력에서 제외한다. 이를 “다시 처리하지 않음”이나 “대기하지 않음”으로 바꾼 초안은 의미가 달라질 수 있다. [구현 원문](https://github.com/vitejs/vite/commit/e6f6b3e3119256daa837b2dc399058c8aa45b470)을 대조해 이 한계를 기록했다. 형식 검사 통과를 사실성 통과로 집계하지 않는다.

README의 절대 보장 표현은 현재 동작과 선택적 자동 검사 범위로 바꿨다. 사용자가 원문을 검토해야 한다는 안내를 유지한다.

## 목적 달성을 위한 제품 개선 — 2026-10-07

비평에서 확인한 ‘복사가 게시로 추정됨’, ‘채널을 옮겨도 업데이트로 작성됨’, ‘URL 등록 시각으로 성과 측정’, ‘진행 중이거나 동시에 게시한 글로 채널 추천’, ‘형식 통과와 게시 가능한 품질의 혼동’을 보완했다.

### 게시 상태와 관측 기준

- 복사는 실제 게시 이력에 포함하지 않는다. URL 없이도 사용자가 실제 게시를 확인할 수 있으며, 실제 게시 시각과 URL을 나중에 수정할 수 있다. 기존 URL 등록 요청도 그대로 받는다.
- 첫 소개 여부는 채널별 게시 확인으로 판단한다. 이미 알린 채널과 새로운 채널을 함께 사용할 때 소개용 판단 각도를 업데이트에 재사용하지 않는다. 연결한 소개 초안의 게시 시각을 생성 시각보다 앞선 날짜로 고쳐도 실제 게시 확인을 인정한다.
- 게시 등록·시각 수정·삭제는 실제 게시 순서에 맞춰 변경 원장을 동기화한다. 초안과 다른 채널·언어로 게시를 등록하거나 미래 시각을 입력하면 거부한다.
- 관측 중, 완료, 자료 부족을 구분한다. 7일이 지난 뒤 발행 전 기준선과 6~7일의 마지막 일 단위 스냅샷이 있는 관측만 완료로 본다. 기준선이 2일보다 오래됐으면 자료 부족이다.
- 같은 저장소에 7일 안에 여러 글을 올렸다면 스타를 균등 배분하지 않고 채널별 기여 구분 불가로 표시한다. 진행 중·자료 부족·동시 게시의 스타는 채널 평균과 추천에서 제외한다. 완료된 스타 관측도 홍보의 인과 효과는 아니다.
- 오래된 완료 관측이 최근 60개 스냅샷 제한 때문에 사라지지 않도록 전체 저장 이력을 사용한다. 표시하는 최근 100개 게시물 밖의 동시 게시도 기여 판단에 포함한다.
- 게시글별 방문·설치·가입 수치를 외부 분석에서 확인해 직접 기록할 수 있다. 자동 반응 수집이 있는 글도 입력 가능하다. 0은 측정값으로, 빈 값은 미측정으로 보존하며 정수가 아닌 값과 음수는 API에서 거부한다. 누적 반응 평균은 7일 반응처럼 표현하거나 추천에 전달하지 않는다.

### 초안과 첫 사용

- 판단은 이름 붙인 독자의 과업과 이번 변화의 가치를 먼저 설명한다. 숫자·실패담이 없다는 이유만으로 유용한 기능을 무의미한 작업으로 취급하지 않도록 지시한다. 기존 사용자 루브릭 가중치는 유지한다.
- 긴 채널도 기본적으로 하나의 변화에 집중하고 같은 과업에 직접 연결되는 보조 변화 하나만 허용한다. 전체 변경 목록은 명시적으로 요청할 때 작성한다. LinkedIn은 적은 근거를 반복해 문단 수를 채우지 않도록 훅과 링크만의 두 문단을 허용한다. Show GN도 같은 사실을 여러 절에서 반복하지 않도록 변경했다.
- 소개 글은 실제 과업을 첫 문장에 두고, 일반적인 ‘개발자를 위한 도구’나 중복 검토 안내에 짧은 글의 공간을 쓰지 않도록 보완했다. 기술 동작이 모호하면 다른 사실을 선택하거나 원어를 유지하며 의미를 더 강하게 바꾸지 않도록 지시한다.
- 신규 계정의 기본값은 한국어 X 초안 하나다. Inbox에서 첫 채널과 언어를 직접 선택하고 이후 설정에서 확장할 수 있다. 이미 저장된 채널 설정은 바꾸지 않는다. 단일 채널 설정을 API 검증이 거부하던 문제도 고쳤다.
- Inbox는 검토 가능한 초안을 먼저, 그 안에서는 높은 점수를 먼저 보여준다. 다음 검토 추천을 함께 제공하고, 첫 저장소 선택에서는 프로젝트 하나부터 시작하도록 안내한다.

### 검토 결과와 실제 사용자 평가

활성 검토 시간을 세션별 누적값으로 기록한다. 화면이 보이고 창에 포커스가 있는 시간만 세고, 같은 세션 재전송은 중복으로 합산하지 않는다. 주기 저장과 화면 이동·복사·버림 시 최종 저장을 사용하며 기록 실패는 주 작업을 막지 않는다. 지원되지 않는 브라우저에서는 시간 기록을 생략한다.

문체 화면에서 검토한 초안의 복사·게시 확인·미완료·버림과 사유·재작성·사실 오류 보고를 함께 보여준다. 양수의 시간을 측정한 복사 초안의 활성 검토 시간 중앙값을 표시하고, 수정량만으로 정확성이나 학습 효과를 주장하지 않는다. 시간은 기능 적용 이후부터 관측하며 외부 검토·편집·게시, 여러 창의 중복 시간, 전송 실패가 있어 전체 과업 시간과 같지 않다. 복사·게시 수는 독립적인 관측 건수다.

`0016_draft-reviews`는 검토 세션 테이블 하나를 추가한다. 기존 게시·초안 데이터는 수정하지 않으며, 검토 기록은 계정 내보내기·삭제에 포함된다. 기존 서버 시작·수동 마이그레이션 경로를 사용한다. 새 외부 분석 서비스나 운영 의존성은 추가하지 않았다.

[실제 사용자 과업 평가 절차](../experiments/README.md#실제-사용자-과업-평가--2026-10-07)를 추가했다. 개발자 5~8명의 직접 작성과 소문 사용을 자료·순서를 바꿔 비교하고, 사실 수정·게시 준비 시간·포기 이유·게시 여부·다음 변경 때 재사용을 기록한다. 실제 참가자 평가·모집·연락은 수행하지 않았으며 시간 절약이나 재사용 효과는 아직 입증되지 않았다.
