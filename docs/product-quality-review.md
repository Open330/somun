# 게시 가능한 초안 품질 보완

## 발견한 문제와 변경

1. 프롬프트는 근거가 없는 숫자·한계를 생략하도록 했지만 lint는 그것들이 없다고 경고했다. 숫자·한계 존재를 의무화하는 검사를 제거했다. 내용이 없는 형식 채우기를 유도하지 않는다.
2. 사용자 수정 저장 시 생성 단계의 한계 검사가 빠졌다. 두 경로가 같은 프로젝트 프로필·글감 근거로 검사하도록 통일했다.
3. 근거에 없는 수치가 있어도 형식 검사를 통과할 수 있었다. 제공된 사실 블록과 수치를 대조해 확인 대상을 표시한다. URL 숫자와 목록 번호는 제외하고, 버전의 v 접두사와 천 단위 쉼표는 정규화한다. 퍼센트와 단순 개수는 구별한다.
4. 경고 설명이 배지의 hover 정보에 머물렀다. 초안 위에 ‘초안에서 확인할 부분’을 펼쳐 원문 확인이 필요한 이유를 읽을 수 있게 했다. 표시 결과는 저장된 초안 기준이며 저장 후 다시 검사한다고 안내한다.
5. Show HN/GN 형식이 근거 없는 문제 상황·비교·한계를 유도했다. 근거 없는 섹션을 생략하고, 저장소 연결만으로 작성자가 소유자·개발자·출시자라고 추정하지 않도록 지침을 보완했다.
6. forks를 모를 때 Facts에 0으로 표시하던 부분을 생략하도록 수정했다.

## 검증

- 전체 24개 파일 119개 테스트 통과. 6개 채널 모두 숫자·한계를 강제하지 않는지, 생성과 수정 저장의 경고가 유지되는지 검사한다.
- 린트·타입 검사·프로덕션 빌드 통과. 프롬프트 후속 보완 후 관련 회귀 검사 44개와 빌드도 다시 통과했다.
- 고정된 공개 Vite 릴리스 자료를 사용해 Show HN 영어와 Show GN 한국어를 실제 모델로 생성했다. 운영 DB나 외부 게시에는 반영하지 않았다.
- 첫 생성은 자동 경고가 없었지만, 사람이 읽어보니 출처에 없는 대규모 코드베이스 병목, 작성자 출시 표현, 변경 사항을 도구 비교로 분류한 문제가 있었다. [첫 결과](generation/quality-review-before.json)를 보존하고 지침을 수정해 [재생성 결과](generation/quality-review.json)를 별도로 기록했다.

## 재생성 관찰

Show HN(약 12.9초)은 출처에 없는 대규모 코드베이스 병목 설명을 제거하고 네 가지 변경을 직접 설명했다. Show GN(약 37.9초)은 “출시했습니다” 대신 “변경 사항입니다”로 시작했고, 근거 없는 도구 비교 섹션과 한계를 넣지 않았다. 두 결과 모두 현재 자동 규칙을 통과했다. 이는 이 표본에 대한 관찰이며 매번 같은 결과를 보장하지 않는다.

## 검사 범위

수치 대조는 자동 사실 판정이 아니다. 같은 숫자가 근거에 있어도 문맥·단위·인과관계가 다를 수 있다. 번역 오류, 수치 없는 과장, 요약 단계의 오류는 별도 원문 검토가 필요하다. 검사에 쓰는 근거는 현재 글감·프로필이며 과거 생성 시점의 불변 스냅샷은 아니다.

이번 결과는 채널 2개·자료 1개의 표본이다. 모든 모델과 채널의 품질이나 실제 사용자 시간 절약을 검증한 것은 아니다. 기존 X·Threads 결과와 함께 사례를 늘리고, 실사용에서 검토 시간·사실 수정·게시 가능 여부를 평가해야 한다. GitHub 최초 연결 권한 정책과 운영 배포는 이전 보고서의 미완료 항목으로 남아 있다.
