# 실제 생성 검증 — 2026-09-22

## 실행 범위

`.env`에 이미 설정된 Gemini 서버 키로 앱의 `runStep` → `runLlm` → `applyResult`를 실제 실행했다. 공개 GitHub 릴리스 두 건을 수집하여 별도 인메모리 DB에 넣었다. 운영 DB·기존 사용자 글감은 변경하지 않았고 외부 게시도 하지 않았다. 네트워크 응답이나 생성문을 mock으로 대체하지 않았다.

- [create-vite@9.2.1](https://github.com/vitejs/vite/releases/tag/create-vite%409.2.1): 의존성 업데이트만 있는 부정 사례.
- [Vite v8.3.0](https://github.com/vitejs/vite/releases/tag/v8.3.0): 빌드·CRLF 처리·경로 판정·프록시 변경이 있는 사례.
- 각 자료에서 요약과 판단을 실행했다. 판단은 자동 초안 기준에 미달했으므로, 초안 품질을 확인하려고 수동 초안 경로로 X 영어와 Threads 한국어를 요청했다. 자동 추천 성공 사례로 집계하지 않는다.
- 수정 전 4개, 수정 후 2개 초안이 실제 생성됐다. 수정 후 부정 사례는 초안 0개로 차단됐다. 마지막 판단 지침 변경은 별도의 실제 판단 호출로 확인했다.

## 수정 후 생성문

### X · 영어

> Vite now avoids settling seen preload dependencies during builds.
>
> Code frame positions handle CRLF line endings and proxy context matchers are pre-compiled at server creation.
>
> v8.3.0: https://github.com/vitejs/vite

### Threads · 한국어

> vitejs/vite v8.3.0 버전을 발표했습니다. 빌드 과정에서 이미 확인된 프리로드 의존성을 다시 처리하지 않도록 수정하여 성능을 높였습니다.

수정 후 표본에서는 숫자·한계를 새로 만들거나 확인용 빈칸을 넣지 않았다. X는 216/280자, Threads는 83/500자다. 문장 자연스러움과 기술적 의미의 정확성은 여전히 사람의 검토 대상이다.

## 검증과 남은 한계

- 생성문을 테스트 서버 DB에 복원한 뒤, mock 없는 실제 앱 HTTP API로 초안 화면을 읽었다. 1440px·390px × X·Threads 네 조합에서 가로 넘침·실행 오류·axe WCAG 2 A/AA 및 2.1 AA 위반이 없었다.
- 전체 18개 파일의 테스트 79개, 린트·타입 검사·프로덕션 빌드와 `git diff --check`가 통과했다.
- 새 회귀 테스트는 근거 없는 생성 차단, 근거 있는 생성 유지, 자동 큐 차단과 린트 상세 설명을 검증한다.
- 소수의 공개 자료와 기본 문체를 확인한 결과다. 모든 모델·문체·채널의 사실 정확성이나 한국어 품질이 보장된다는 뜻은 아니다. 린트는 개인 경험의 진위를 검증하는 모델이 아니다.
- 무료 키의 재시도와 대체 모델 때문에 생기는 긴 대기 시간 자체는 해결되지 않았다. 여러 채널을 동기 생성하는 요청은 프록시 제한을 넘을 수 있다. 이후 [비동기 생성 큐 개선](generation-queue.md)에서 영속적인 상태와 즉시 접수 응답을 구현했다. 모델 자체의 응답 지연은 여전히 남는다.
- 기존에 생성된 초안과 판단 결과는 자동으로 수정하지 않는다. 화면 예시의 판단은 초안 생성 당시 결과이며, 마지막 판단 지침 재검증 결과는 JSON의 `judge_recheck`에 따로 기록했다.
