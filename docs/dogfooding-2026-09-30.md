# 소문 dogfooding 결과 — 2026-09-30

첫 글감 수집과 초안 검토에서 사용자가 잘못된 상태를 정상으로 받아들이는 문제가 가장 먼저 해결할 대상이다. 브라우저에서 기능·UX 문제 6건을 재현했고, 기존 소개 초안과 프로젝트 프로필에서 콘텐츠 품질 문제 1건을 확인했다.

## 후속 개선과 재검증 — 2026-10-04

첫 결과에 필요한 채널·언어와 모델 연결을 온보딩에서 안내하고, 채널이 없으면 준비·전체 재작성을 막아 해당 설정으로 연결한다. 자동 처리와 API도 채널 없는 작업을 큐에 넣지 않는다. 설정 저장 직후 이탈 보호가 남는 경합과 브라우저 검증 스크립트의 저장 대기를 보완했다.

생성 보정은 경고 개수를 줄이면서 새로운 위반을 만들지 않을 때만 채택한다. 근거 관련 경고가 남는 경우 그 상세 내용까지 비교하여 근거 없는 40%를 80%로 바꾸는 보정을 거부한다. 서버와 로컬 워커가 같은 기준을 사용한다. Show GN의 Markdown 절 제목을 인정하고, 한국어 본문의 `소셜 media`·`마케팅 copy`를 경고·보정 대상으로 추가했다. 경고 이름도 사용자에게 읽히는 표현으로 표시한다. 복사 기록은 보존하되 근거 없는 수치·한계·이름 오류·혼용 표현이 남은 글은 문체 예시로 추가하지 않는다.

프로필 생성에서 독자 대상 문구를 저자의 동기로 추론하거나 숫자 검사를 모든 사실의 검증으로 확대하지 않도록 지시했다. 초안에는 근거 없는 작성자 역할을 피하도록 하고, X 첫 소개는 핵심 기능 하나와 짧은 두 문장을 우선하도록 했다. README도 자동 검사 범위와 복사 예시·검토된 지침의 사용에 맞춰 수정했다.

별도 DB에서 공개 `Open330/somun` 저장소를 실제 GitHub API로 수집하여 신호 29건과 글감 1건을 만들었다. Gemini `gemini-3.5-flash-lite`로 프로필·요약·판단 및 X 한국어/영어·LinkedIn 한국어·Show GN 한국어 초안을 생성했다. 첫 요청에서 네 초안 완료까지 15.6초, 이후 네 초안 재생성은 11.5초였다. 이는 큐 대기를 포함한 단일 프로젝트 관측값이다.

초기 표본에는 근거 없는 저자 역할, 사실 검증 범위 확대, 영어 X 길이 초과가 있었다. 보완 후 네 채널의 한 회차는 형식 검사를 통과했지만, 긴 글에는 커밋 개수 나열과 어색한 표현이 남았다. 후속 X 표본의 `소셜 media`는 새 검사로 재현했고, 마지막 실제 생성은 `소셜 미디어`로 작성되어 경고가 없었다. 일부 Show GN 표본은 여전히 저자 역할을 암시하므로 프롬프트 강화가 의미 검토를 대체한다고 볼 수 없다.

브라우저에서 한국어 X 초안을 직접 고쳐 복사했으며 클립보드의 채널별 추적 링크와 실제 복사 표본 1건을 확인했다. 발행 기록은 0건이고 외부 게시를 하지 않았다. 자동화에서 관측한 수정·복사 시간이나 단 한 번의 후속 생성으로 사람의 시간 절약·문체 학습 효과를 주장하지 않는다.

별도 fixture 환경에서 민서·알렉스·지수 시나리오 총 15단계를 통과했다. 첫 소스 연결·모델 누락 복구·수정과 복사·게시 링크 보존·다른 언어와 채널의 후속 작성·설정 및 저장 오류 복구를 검증했다. 페이지 오류는 없었으며 390px 모바일에서 가로 넘침이 없었다. OAuth 로그인과 실제 SNS 게시까지 검증한 것은 아니다.

검증: 56개 테스트 파일의 455개 테스트, 타입 검사, lint, 웹 포맷, 웹/서버 빌드를 통과했다. 이번 변경에는 DB 스키마 변경이 없다. 공개 입력과 생성 표본 및 관측 기록은 [검증 자료](generation/dogfood-20261004.json)에 보관했다. 아래 9월 30일 기록은 당시 상태를 설명한다.

## 범위와 검증 방법

- 현재 작업 트리의 웹을 빌드하고 별도 SQLite DB와 API 포트 `18790`에서 실행했다. 제품 코드는 수정하지 않았다.

- 기존 DB는 읽기 전용으로 열었다. 후보 4건·판단 8건·초안 36건만 격리 DB에 복제해 검토·발행 동작을 시험했다. 실제 발행이나 운영 데이터 변경은 하지 않았다.
- GitHub 인증이 없는 경우와 환경에 이미 설정된 토큰을 사용하는 경우를 나눠 확인했다. 정상 저장소 수집은 실제 GitHub API로 대조했다.
- 새 LLM 초안 생성, 실제 SNS 게시, 배포 서비스 OAuth 로그인은 검증하지 않았다. 콘텐츠 평가는 저장된 초안에 한정한다.
- 아래 개선안과 완료 조건은 제안이다. 구현이나 수정 후 검증을 완료했다는 뜻은 아니다.

## 1. GitHub URL을 붙여 넣으면 정상 연결처럼 보이지만 수집되지 않는다

**재현**

1. 연결 관리의 직접 지정에 `https://github.com/Open330/somun`을 입력한다.
2. ‘저장소를 연결했습니다’가 표시되고 소스에도 URL이 그대로 남는다.
3. GitHub 토큰이 설정된 환경에서 ‘새 변경 가져오기’를 누른다.
4. ‘확인을 마쳤습니다. 새로 가져올 변경은 없습니다’가 표시되고 `lastError`도 없다.
5. 같은 소스의 대상을 `Open330/somun`으로 바꿔 다시 수집하면 **새 변경 29건**을 가져온다.

**원인:** [Connectors.tsx](../src/web/pages/Connectors.tsx)는 주소도 허용하는 안내를 제공하지만 입력을 trim만 한다. [collect.ts](../src/app/collect.ts)의 `expandTargets`는 `/repos/${target}`으로 요청한다. [client.ts](../src/infra/github/client.ts)는 404를 null로 반환하므로 잘못된 주소가 ‘변경 없음’으로 처리된다.

**개선:** 저장 시 GitHub URL을 `owner/repo`로 정규화하고 지원하지 않는 형식은 필드에서 안내한다. 저장소를 찾지 못한 경우와 변경이 없는 경우를 구별한다.

**완료 조건:** URL·`owner/repo`가 같은 저장소로 정규화된다. 없는 저장소는 ‘찾을 수 없음 또는 접근 권한 없음’을 표시하고 성공 수집으로 기록하지 않는다.

## 2. 이전 판을 보는데 최신 판의 점검 결과가 나온다

**재현:** `/c/8`의 X → EN에서 v5 대신 v3을 선택한다. 본문은 실제 **405자**인 v3으로 바뀌지만 화면에는 **121 / 280자**, **형식 점검 통과**가 남는다. v3 자체의 저장된 lint에는 `length: false, 405/280`이 있다.

**원인:** [DraftPanel.tsx](../src/web/pages/candidate/DraftPanel.tsx)는 본문을 `shown`에서 가져오지만, `count`는 `body`, `checks`와 `LintBadges`는 `latest.lint`에서 가져온다.

**개선:** 읽기 상태에서는 선택한 판의 본문·제목·lint·생성 모델을 일관되게 사용한다. 편집 상태의 글자 수는 현재 입력값을 사용한다.

**완료 조건:** v3에서 405/280 및 길이 경고가 나타나고 v5로 돌아오면 121/280 및 통과로 바뀐다. 버전별 다른 lint·모델도 선택한 판과 일치한다.

## 3. 잘못된 프로젝트 배경이 여러 채널로 전파된다

**확인한 데이터**

- 저장된 소문 프로필의 사용자 편집 `limitations`에 `Code sources are GitHub repositories only (plus RSS blogs, npm downloads, and coding-agent session summaries)`가 있다.
- Show GN 한국어 v8은 ‘GitHub 저장소만 지원합니다 (RSS 블로그, npm 다운로드, 코딩 에이전트 세션 요약 포함)’라고 쓴다.
- X 한국어 v4는 ‘GitHub 저장소만 지원합니다’로 단정한다. 두 초안의 저장된 lint는 모두 통과한다.

이는 이번 실행에서 모델이 새로 지어낸 오류로 확인된 것이 아니다. **이미 저장된 사용자 편집 프로필의 모순이 초안에 이어진 사례**다. [profiles.ts](../src/app/profiles.ts)는 사용자 편집 필드를 재생성 뒤에도 우선하며, [prompts.ts](../src/core/prompts.ts)는 이를 사실 블록으로 전달한다.

**개선:** 우선 해당 프로필에서 지원 범위와 실제 제약을 분리해 정정한다. 제품에서는 프로필의 사용자 수정값과 근거를 검토하기 쉽게 표시하고, 재생성 후에도 유지된 수정값임을 알린다. 전면적인 의미 검증 모델 추가보다 이 흐름을 먼저 보완하는 것이 단순하다.

**완료 조건:** 정정된 프로필로 대표 채널 초안을 생성해 블로그 지원 등 실제 기능과 모순되는 문장이 없는지 사람이 검토한다. 자동 형식 점검 통과와 내용 검증 완료는 구분한다.

## 4. 수집 실패 원인을 알고도 사용자에게 전달하지 않는다

**재현:** GitHub 인증이 없는 격리 환경에서 수집하면 API의 `lastError`는 ‘GitHub 토큰이 없습니다. GitHub App을 설치하거나 GITHUB_TOKEN을 설정하세요’이다. 글감에서는 ‘일부 소스를 확인하지 못했습니다’, 연결 관리에서는 ‘주소와 접근 권한을 확인해 주세요’만 나온다.

**원인:** [Connectors.tsx](../src/web/pages/Connectors.tsx)는 `lastError` 존재 여부만 보고 고정 문구를 출력한다. GitHub App이 미설정인 환경에서는 이 화면에 연결 버튼도 없어 사용자가 해결 경로를 찾기 어렵다.

**개선:** 인증 누락·저장소 접근 불가·요청 제한을 사용자용 오류 유형으로 구분하고 적합한 복구 동작을 제시한다. 원시 서버 오류를 무조건 노출할 필요는 없다.

**완료 조건:** 인증 누락에는 App 연결 또는 운영자 설정 필요 안내, 요청 제한에는 재시도 가능 시각, 접근 불가에는 저장소·권한 확인 안내가 나온다.

## 5. X 초안에 LinkedIn 링크를 저장해도 X 발행으로 기록한다

**재현:** X → EN의 게시글 링크에 `https://www.linkedin.com/posts/dogfood-example`을 입력해 저장한다. 성공하며 발행 기록에서도 **X**로 분류된다. 테스트 링크를 외부에 게시하지는 않았다.

**원인:** 화면과 [publications.ts](../src/app/publications.ts)는 URL과 선택 채널의 대응을 확인하지 않는다.

**개선:** 주요 채널의 알려진 호스트와 링크가 다르면 저장 전에 불일치를 알리고 채널 선택을 바로잡게 한다. 단축 URL·사용자 도메인은 일괄 차단보다 명시적인 확인이 적합하다.

**완료 조건:** X에 LinkedIn URL 입력 시 무경고 저장되지 않는다. 기존 링크 수정에도 같은 검사가 적용된다. 정상 채널 URL은 그대로 등록할 수 있다.

## 6. 설정을 수정하다 다른 화면으로 가면 입력이 사라진다

**재현:** 설정 → 모델·키에서 분석 모델을 `dogfood-unsaved-model`로 변경하고 저장하지 않은 채 사이드바 글감으로 이동한다. 안내 없이 이동하며 모델 설정을 다시 열면 기존 값 `gemini-3.5-flash-lite`로 돌아간다.

**원인:** [Settings.tsx](../src/web/pages/Settings.tsx)의 편집값은 컴포넌트 상태에만 있고 이탈 보호가 없다. 초안 편집에는 이미 미저장 보호가 있어 동작도 일관되지 않다.

**개선:** 명시적으로 저장하는 설정 입력에도 수정 중임을 표시하고, 미저장 내용이 있는 경우 이동·새로고침에서 이탈을 확인한다.

**완료 조건:** 미저장 설정에서 이동 시 계속 편집 또는 버리고 이동을 선택할 수 있다. 저장 후에는 경고가 없다.

## 7. 복사하지 않고 발행 링크만 등록해도 ‘그대로 사용 100%’가 된다

**재현:** 격리 DB의 미복사 X 초안에서 복사 버튼을 누르지 않고 게시 링크만 등록한 뒤 문체 화면으로 이동한다. ‘학습 효과 복사한 초안 1건 기준’, ‘그대로 100% · 고친 양 0% · 1건’이 표시된다. 활성 내 예시는 0개다.

**원인:** [publications.ts](../src/app/publications.ts)는 발행 등록 시 초안 상태를 `copied`로 변경한다. [learning-stats.ts](../src/app/learning-stats.ts)는 이 상태를 실제 복사 표본으로 취급하며 편집 이력이 없으면 수정량 0을 채운다. 외부 게시 화면에서 수정했는지는 알 수 없다.

**개선:** 실제 복사·수정량을 관측한 표본과 URL만 등록한 발행을 분리한다. 관측하지 않은 수정량은 ‘알 수 없음’으로 두고 그대로 사용 비율에서 제외한다.

**완료 조건:** 링크만 등록한 초안은 복사 표본·무수정 비율에 들어가지 않는다. 실제 복사한 초안은 기존처럼 집계된다.
