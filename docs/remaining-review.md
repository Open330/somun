# 후속 개선 및 운영 검증

## 이번 변경

- GitHub 설치 소유자 변경 차단: 이미 연결된 설치는 같은 소유자만 갱신한다. GitHub API 응답 대기 중 다른 소유자가 연결한 경우에도 조건부 UPDATE로 덮어쓰지 않는다.
- **최초 연결 권한은 미완료**: 현재 앱 로그인은 GitHub 사용자 접근 권한의 증거가 아니다. 관리자 전용 연결과 사용자별 GitHub OAuth 중 정책 합의가 필요하다. 이 결정 전에는 다중 사용자에게 설치 연결을 공개하지 않는다.
- React Router `useBlocker`로 SPA 링크·뒤로가기 이동을 차단하고 수정 유지/버리기를 제공한다. 외부 이동·새로고침은 기존 브라우저 이탈 보호를 유지한다.
- 재판단 후에도 이미 작성된 초안은 검토 목록에 남는다.
- 사용량 전송은 Reporter 인스턴스 내 진행 중 Promise를 공유한다. 타이머와 종료 시 flush가 같은 배치를 중복 전송하지 않는다. 여러 서버 프로세스 간 잠금은 아니므로 사용량 전송 서버는 한 프로세스로 운영하고 수신 측 eventId 중복 제거 계약을 유지한다.
- 사용량 재시도 소진 조회·복구와 SQLite 온라인 백업 명령 추가.

## 의존성

Anthropic SDK 0.91.1, Vitest 4.1.11로 업데이트했다. Testing Library DOM peer 의존성을 명시하고 Vitest 설정 타입을 사용한다.
Drizzle Kit가 간접 참조하는 `@esbuild-kit/core-utils`의 esbuild만 `^0.25.12`로 제한적으로 override한다. 이 override는 상위 패키지가 안전한 버전을 채택하면 제거할 수 있다. 자동 강제 수정이 제안한 Drizzle Kit 구버전 다운그레이드는 적용하지 않았다.

`npm audit`의 취약점은 0건이다. 이는 알려진 의존성 권고 기준이며 애플리케이션 전체 보안 검증을 대체하지 않는다.

## 실행 가능한 운영 절차

Node 22에서 프로젝트 루트 기준으로 실행한다. `.env`의 `DATA_DIR`가 대상 DB를 가리키는지 먼저 확인한다.

```sh
npm run usage:outbox -- status
npm run usage:outbox -- retry '출력된-event_id'
npm run db:backup -- /안전한/경로/새로운-backup.db
```

조회는 원문·키·오류 응답을 출력하지 않는다. retry는 지정한 재시도 소진 행만 초기화하며 eventId를 유지한다. 서버의 다음 flush 주기에 전송한다. 복구는 실행 중인 전송과 충돌하지 않도록 서버를 정지한 상태에서 수행한다.

백업은 SQLite backup API를 사용해 WAL에 커밋된 내용까지 일관된 파일로 저장한다. 대상 디렉터리는 먼저 준비해야 한다. 기존 파일을 덮어쓰지 않으며 백업 권한은 0600이다. 백업에는 앱 데이터와 저장된 자격 증명이 포함될 수 있으므로 접근을 제한한다.

배포 순서:

1. 서버와 CLI 워커를 정지한다. 사용 중인 릴리스와 설정을 보관한다.
2. 위 명령으로 DB 백업을 만들고 별도 임시 디렉터리에 복사해 복원 검사를 수행한다. 실제 DB에 덮어써서 검사하지 않는다.
3. 복사본에서 `DATA_DIR=/복원검사/디렉터리 npm run db:migrate`를 실행하고 SQLite `PRAGMA integrity_check`, `PRAGMA foreign_key_check` 및 주요 데이터 수를 확인한다.
4. 서버와 CLI 워커를 같은 릴리스로 업데이트한다. claimToken 계약과 0007/0008 마이그레이션을 함께 적용한다.
5. 서버를 시작해 `/health`, 로그인, 글감 조회, 생성 접수/완료, 실패 재시도와 워커 연결을 확인한다.
6. 실패 시 새 서버·워커를 정지한다. 기존 DB·WAL·SHM을 별도 보관한 뒤, 비어 있는 복원 디렉터리에 백업을 `somun.db`로 복사하고 이전 릴리스와 설정으로 시작한다. 구버전 서버를 마이그레이션된 DB에 바로 연결하지 않는다.

이 문서는 절차다. 이번 작업에서 운영 DB 변경이나 배포를 실행한 것은 아니다.

## 검증 증거와 한계

- 전체 테스트 23개 파일 102개 통과 후 JWT 경계 검사 1개를 추가하고 관련 3개 파일 7개 테스트도 통과했다. 합계 24개 파일 103개 테스트가 검증됐다. 린트·타입 검사·프로덕션 빌드가 통과했고, Drizzle Kit generate는 스키마 변경 없음으로 종료했다.
- 임시 DB에서 WAL을 포함한 백업·복원, 기존 백업 덮어쓰기 거부, 0600 권한, 선택적 사용량 재등록을 실제 실행했다.
- 실제 Chrome 1440px/390px에서 뒤로가기 취소 시 수정 보존, 명시적 버리기 이동을 확인했다. 브라우저 오류·가로 넘침·axe WCAG A/AA 위반 0건: [결과](ux/remaining-browser.json).
- 실제 생성 결과는 [기존 생성 보고서](generation-review.md)와 [큐 검증 보고서](generation-queue.md)에 있다. 이번 변경에서 모든 모델/채널의 실제 생성 품질을 재평가한 것은 아니다.
- 실제 GitHub 설치 왕복, 배포 프록시 뒤 장시간 JWT/SSE 갱신, 운영 데이터 백업·복원, 처음 사용하는 사람의 사용성 평가는 아직 수행하지 않았다.

## 다음 사용성·품질 평가

처음 사용하는 사람에게 설명 없이 소스 연결 → 첫 글감 수집 → 초안 생성 → 수정 → 복사 → 발행 링크 기록을 수행하게 한다. 단계별 성공 여부, 막힌 위치, 첫 초안까지 걸린 시간, 도움 요청 횟수를 기록한다. 성공 기준은 진행 전에 합의한다. 자동 브라우저 테스트를 실제 사용자 평가로 간주하지 않는다.

생성 품질은 6개 채널과 활성 언어별로 릴리스·PR·블로그·빈 근거를 포함한 고정 입력으로 평가한다. 출처에 없는 수치·경험·제약, 링크 정확성, 채널 형식, 수정 없이 사용 가능한 비율을 별도로 기록한다. 현재 형식 lint 통과만으로 사실성을 판정하지 않는다.
