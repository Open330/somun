두 검토자가 모두 탈락시킨 것은 9회차의 aas 한국어 하나입니다("aas는 … 등록해 두고 … 바꿔 씁니다": 도구가 계정을 쓰는 주어로 읽힘). Opus 검토만 탈락시킨 것은 다음과 같습니다.
- aas 영어: 핵심인 계정 전환 누락, 명령어 서식 없음
- Haejo 영어: 첫 줄의 "매달 같은 행"이 원문과 어긋남
- Tend 한국어: "입력이나 선택, 오류로 멈추면"의 번역투

Opus 검토는 같은 계열의 생성본(9회차)에 Codex보다 오히려 엄격했습니다. 같은 모델이라 유리해지는 효과는 보이지 않았습니다.

## 판단 근거: "첫 소개 초안만 로컬 워커" 구성을 권장할 수 있는가

- **품질:** 두 검토자 모두 로컬 워커가 낫다고 봤습니다. Opus 판정 3 → 4·6, Codex 판정 5 → 10·9입니다. 기준 8/10은 Codex 판정에서만 넘습니다. Opus 판정 기준으로는 Opus 5.5 로컬(6/10)이 지금까지 가장 높지만 미달입니다.
- **비용·호출:** 로컬은 서버 공유 키를 쓰지 않습니다. 초안 한 편에 생성 1회, 보정은 거의 없었습니다. flash-lite 서버 경로는 비평·수정까지 한 편에 평균 3회입니다.
- **시간:** Sonnet은 flash-lite와 비슷하고(10개 약 77초), Opus는 약 1.8배(약 132초)입니다. 첫 소개는 저장소마다 한 번이라 체감 차이는 작습니다.
- **제약:** 로컬 워커는 사용자의 컴퓨터에서 Claude Code가 돌고 있어야 합니다. 설정이 `local-agent`이면 지금은 프로필·판단까지 로컬로 갑니다. "초안 단계만 로컬"은 측정용으로 설정을 중간에 바꾼 것이고, 서비스에는 단계별로 실행 위치를 고르는 기능이 아직 없습니다.

**권장:** 첫 소개 초안만 로컬 워커(Opus 5.5)로 돌리는 구성은 품질 근거가 있습니다. 다만 Opus 판정 기준 8/10에는 아직 못 미칩니다. 채택하려면 두 가지가 필요합니다. 하나는 단계별 실행 위치 설정(소개 초안만 로컬)이고, 다른 하나는 로컬 경로에도 서버와 같은 비평→수정 루프를 붙이는 것입니다(9회차 탈락 4건은 모두 문장 단위로 고칠 수 있는 유형). 그 뒤 같은 방법으로 다시 재는 것을 제안합니다. 운영 기본값 변경은 사용자가 정합니다.
