# 생성 초안 무수정 게시 측정 — 2026-11-12

목표는 "소문이 생성한 첫 소개를 한 글자도 고치지 않고 게시할 수 있다"입니다. 완료 기준은 사용자의 프로젝트 5개로 X 한국어·영어 첫 소개 10개를 생성했을 때 다음 두 조건을 모두 만족하는 것입니다.

- 생성본이 길이와 lint를 통과합니다.
- 독립 검토자가 "그대로 게시 가능"으로 판정한 것이 **10개 중 8개 이상**입니다.

**결과: 기준에 미달합니다.** 마지막 측정(7회차)은 3/10이고, 가장 높았던 회차는 5/10입니다. 길이·lint는 생성본 10개가 모두 통과합니다. 남은 탈락은 의미 수준의 문제이고, 원인은 생성 모델로 판단해 모델 선택을 사용자 결정으로 올렸습니다(아래 "다음 결정").

## 방법

- 대상: Open330/tend, Open330/haejo, Open330/aas, Open330/barshelf, jiunbae/oh-my-prompt. 각각 X 한국어·영어 첫 소개를 만듭니다.
- 생성: 회차마다 새 격리 DB로 그 회차의 코드를 담은 서버를 띄우고, 실제 GitHub API로 수집합니다. 이어 프로필 → 판단 → 초안을 생성합니다. 서비스 API만 썼고, **사람이 고친 판은 쓰지 않았습니다.** 스크립트는 [`intro-eval-20261112/run.py`](intro-eval-20261112/run.py)입니다.
- 모델: 공유 Gemini `gemini-3.5-flash-lite`(서버 고정). 무료 키를 썼고, 2회차까지는 2개, 5회차부터는 6개입니다.
- 판정: 회차마다 **새로 띄운** Opus 5.5 검토자에게 같은 지시문을 줬습니다. 검토자는 생성본과 각 프로젝트의 홈페이지·README 원문을 대조합니다. 하나라도 해당하면 탈락입니다.
  - 원문에 없거나 과장된 사실
  - 원어민답지 않은 문장(번역투·주어 누락·띄어쓰기 등)
  - 광고 말투
  - 처음 보는 사람이 무엇인지 알 수 없음
  - 군더더기
  - 형식(링크·길이) 문제
  
  판정 자료는 [`intro-eval-20261112/<회차>/verdicts.json`](intro-eval-20261112/)에 있습니다.
