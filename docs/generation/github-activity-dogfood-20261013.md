# GitHub 활동 기반 운영 dogfooding

원래 GitHub 로그인 계정의 기존 연동을 사용해 최신 변경을 수집했다. somun, kongbu, munjit의 게시되지 않은 활동 글감에서 일반 다이제스트·판단을 실행하고 한국어 X·Threads 초안을 생성했다. 계정의 모델, 문체, 채널, 임계값은 변경하지 않았다. 기존 초안과 게시 기록은 보존한다.

## 배포 전 관찰

- 세 글감 모두 5점·보류로 판단돼 자동 초안은 나오지 않았다. 수동 생성은 게시 기록 부재에 따라 처음 소개하기가 기본이었다. 이 결과를 자동 생성 성공으로 집계하지 않는다.
- 기본 소개 6개 중 자동 검사 5개 통과. munjit X는 필수 저장소 URL의 소유자 `jiunbae`를 프로필 금지어로 검출했다. 자동 보정은 링크를 빼 `has_link`를 위반했고 채택되지 않았다.
- 변경 소식을 명시해 6개를 추가 생성했다. Threads 세 개 모두 업데이트 대신 일반 소개를 썼다. URL을 본문 밖에 두는 채널에서 마지막 프롬프트 분기가 목적별 작성 지침을 누락했다.
- kongbu X의 내부 실패 후 할당량 복구 설명은 PR 제목에 있는 범위보다 자세한 정책(내부 할당량 오류, UTC 하루 최대 세 번 등)을 보존하지 못했다. 수집된 PR 제목만으로 세부 조건을 확인할 수 없는 문제다.
- 오래된 README 설명에서 Azure OpenAI를 가져온 소개가 있었다. 현재 저장소 코드는 Gemini와 선택적 Azure 경로를 모두 가지므로 README에 있다는 사실만으로 현재 운영 경로를 확정할 수 없다.

## 수정

프로필 금지어는 HTTP(S) URL을 뺀 제목·본문에서 검사한다. URL 자체의 소유자와 경로는 편집 표현이 아니다. 본문·제목·마크다운 링크 라벨의 실제 금지어는 계속 검출한다.

본문 링크 위치와 목적별 작성 지침을 독립적으로 넣는다. 답글 링크와 링크 없음 채널도 첫 소개/변경 소식 지침을 받는다. 짧은 업데이트는 근거 요약의 구체적 변경으로 시작하고, 두 문장 채널은 변경 한 문장과 필요한 작업 질문 한 문장을 사용하도록 한다.

초안이 없을 때와 초안 메뉴에 `변경 소식으로 쓰기`를 추가해 사용자가 게시 기록 없이도 업데이트를 명시할 수 있게 했다. 기존 소개 자동 선택은 유지한다.

임계값 변경, 허위 게시 기록, 사실 확인 완료 표시를 사용하지 않는다. 변경은 URL 오탐과 목적 지침 누락 두 재현 가능한 결함과 목적 선택 경로에 제한한다. PR 본문 수집, 원자료 최신성, 글감 판단 보정은 이 수정으로 해결되지 않는다.

검증은 제한된 실제 운영 사례이며 전체 서비스 성공률이나 사람의 시간 절약을 입증하지 않는다. 수정 전 실패와 수정 후 새 생성은 별도 기록하며, 재작성 성공을 원래 첫 생성 성공으로 계산하지 않는다. 개인 계정·원문·호출 결과는 공개 저장소가 아닌 접근 제한 로컬 기록에 보관한다.

검증 중 기존 로그아웃 테스트가 로컬 부하에서 지연된 화면 로딩과 비동기 로그아웃 시작을 기다리지 못해 실패했다. 화면 로딩 대기 한도와 요청 시작 대기를 명시했으며, 실제 로그아웃 구현은 바꾸지 않는다. 실패 로그를 보존하고 재검증한다.

## PR 본문 조건 보존 후속 개선

목적 지침 수정 후 6개 모두 자동 검사를 통과했지만, 소스 대조에서는 기본 비활성 GitHub App을 사용 중으로 서술하고, 마지막 시도·최소 수량 조건을 빼고, GitHub 릴리스 부재를 운영 미배포로 해석한 오류가 남았다. 자동 검사 통과를 게시 준비 완료로 간주하지 않는다.

GitHub의 기존 PR 목록 응답에 포함된 본문을 신호와 글감 JSON에 보존한다. 재수집으로 기존 제목 전용 신호를 보완하되 신호·글감·초안을 중복 생성하지 않는다. 추가 외부 호출이나 DB 마이그레이션은 없다. 글감에 연결된 최근 20개 본문을 저장하고, 본문당 최대 12000자·프롬프트 본문 합계 48000자로 제한한다. 프롬프트는 본문 단위로 포함하며 수집 중 잘린 원문은 명시한다. 제목·본문은 모델 명령이 아닌 원자료다.

다이제스트·판단·초안에 같은 PR 원문을 전달하고 원자료 대조 화면에서도 검색한다. 기능 플래그, 재시도 단계, 최소 수량, 할당량 종류·환불 상한·예외를 기능과 함께 보존하도록 한다. merge, GitHub release, 운영 배포, 기능 활성화를 구분한다. 짧은 글에서 조건을 다 넣을 수 없다면 단순한 다른 변경을 선택하고 첫 문장을 반복해 분량을 채우지 않는다.

후속 dogfooding 합격 기준은 원문 조건·배포 상태를 왜곡하지 않는 구체적 변경 글, 중복 없는 자연스러운 문장, 원래 계정의 생성·대조·모바일 검토 흐름 정상 동작이다. 기존 실패와 새 버전을 모두 보존하며 실제 게시나 계정 설정 변경 없이 평가한다.

본문 수집 반영 후 세 글감의 일반 판단은 7·7·8점으로 바뀌어 각 하나의 초안을 자동 생성했다. 설정을 보정해 얻은 결과가 아니다. 그러나 긴 소개 글은 부분 결과 반환의 마지막 시도 조건을 여전히 누락하고, 현재 제공자를 확정하지 못하는 프로필 설명을 가져왔다. 이를 성공으로 제외하지 않고 중간 실패로 보존한다.

조건을 나타내는 원문 줄을 추가 요약 없이 작성 직전 다시 보여 준다(합계 최대 8000자). 이는 선택 보조이며 모든 조건을 찾거나 사실을 인증하지 않는다. 일반 소개에서는 독자 과업에 필요하고 최신 원문이 확인해 주는 경우 외에 모델 제공자·이름을 제외한다. 목록 API는 큰 PR·README 본문을 제외하고, 소유자별 상세 API는 대조용 본문을 전달한다. 원자료 대조 화면이 상세 API에서도 짧은 README 발췌만 받던 문제를 함께 수정한다.
