# 소문 UX 점검과 개선 — 2026-09-22

## 왜 덜 완성된 제품처럼 느껴지는가

실제 사용자 인터뷰나 운영 분석이 아니라 **코드 점검과 Chrome의 재현용 데이터로 수행한 사용성 평가**다.
아래의 화면 동작은 재현했으며, 그것이 사용자의 주관적 인상에 미치는 영향은 검증할 가설로 구분한다.

| 재현한 문제 | 사용자가 느낄 수 있는 이유 | 적용한 해결 |
| --- | --- | --- |
| 빈 계정에서 여섯 단계 설정 목록, 초안 0개, 비활성 수집 버튼이 동시에 나타남 | 가치가 보이기 전에 해야 할 일부터 많고 어디서 시작할지 모름 | 완성 예시와 3단계 여정, ‘첫 소스 연결하기’ → ‘첫 글감 가져오기’로 이어지는 안내 |
| GitHub 미연결이면 앱 셸 전체가 동의 화면으로 대체됨 | 다른 소스·설정·기존 작업에 접근하기 어려움 | 연결을 선택 가능한 작업으로 바꾸고 본문 접근 유지 |

| 200 응답 안의 수집 실패나 모델 오류를 성공처럼 안내함 | 버튼을 눌러도 무엇이 일어났는지 알 수 없음 | 부분 실패·모델 오류 확인, 지속되는 인라인 안내와 복구 경로 |
| 로딩과 조회 실패를 구분하지 않는 주요 화면 | 고장인지 기다리면 되는지 판단할 수 없음 | 로딩/빈 상태/검색 결과 없음/오류와 다시 시도 구분 |
| 저장소·이유가 작은 단일 행에 압축되고 모바일에서는 이유를 숨김 | 무엇을 골라야 하는지 판단 근거가 부족함 | 저장소·변경 유형·시각·이유가 보이는 목록, 상태 필터와 검색 |
| 초안보다 긴 근거 패널이 모바일에서 먼저 나옴 | 핵심 작업을 시작하려면 많이 내려가야 함 | DOM에서도 초안을 먼저 배치, 평가 기준과 프로젝트 배경은 펼쳐보기 |
| 복사해야만 게시 링크 입력이 보임 | 이미 올린 글을 기록하려고 불필요한 작업을 반복함 | 게시 링크 입력을 항상 제공하고 저장 즉시 완료 상태 표시 |

| 클립보드·저장 실패에 복구 안내가 없고 짧은 토스트만 사용 | 동작의 성공 여부를 확인하기 어려움 | 실패를 인라인으로 남기고 재시도 가능. 일반 토스트는 타이머 중첩 제거·노출 시간 보완 |

## 조사한 원칙과 대안

- [Carbon: Empty states](https://carbondesignsystem.com/patterns/empty-states-pattern/)는 빈 이유와 다음 행동을 문맥에 맞게 설명하고, 여러 빈 위젯을 쌓기보다 해당 공간을 대체하도록 안내한다. 첫 화면에 결과 예시와 주 행동 하나를 배치했다. 예시는 실제 데이터와 혼동하지 않도록 표시했다.
- [NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)는 핵심 기능을 먼저 보여주고 세부 옵션을 필요할 때 펼치게 하는 원칙이다. 프로젝트 프로필, 판단 점수, 게시 체크리스트, 세션 업로더를 보조 위치로 옮겼다.
- [GOV.UK: Task list](https://design-system.service.gov.uk/components/task-list/)는 순서가 정해진 긴 서비스에 작업 목록을 사용하지 않도록 설명한다. 초안 하나를 얻기 위한 여정에 여섯 가지 설정을 같은 중요도로 나열하는 대신 현재 단계에 필요한 행동을 제시했다.
- [Buffer: Saving and scheduling draft posts](https://support.buffer.com/en-us/articles/saving-and-scheduling-draft-posts-CBLXg1yFXp)는 초안 준비와 발행 준비를 구분한다. 소문에는 자동 게시 기능을 추가하지 않고 ‘검토·수정 → 직접 게시 → 링크 기록’의 구분을 차용했다.
- [W3C: Status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)의 원칙을 따라 성공 안내와 오류를 보조 기술에서도 인식할 수 있도록 `status`/`alert`를 사용했다. 검색·입력 라벨, 필터 선택 상태, 건너뛰기 링크, Escape로 메뉴 닫기를 함께 보완했다.

| 대안 | 장점 | 비용/한계 | 결정 |
| --- | --- | --- | --- |
| 전체 설정 마법사 | 경로가 단순하고 설정 누락 방지 | 기존 사용자 흐름을 막고 첫 결과까지 설정 부담이 큼 | 채택하지 않음 |
| 상태별 칸반 보드 | 작업이 많을 때 진행 상황 비교가 쉬움 | 모바일 폭, 실제 처리 상태 데이터, 드래그 접근성까지 추가 설계 필요 | 후속 검토 |
| 현재 화면을 결과 중심으로 정리 | 기존 기능으로 첫 결과까지 연결, 작은 화면에서도 작동 | 작업 엔진의 실시간 상태까지 해결하지는 않음 | 이번에 채택 |

## 적용 범위

- 앱 셸과 모바일 내비게이션, 첫 사용 안내, 글감 목록, 연결 관리, 초안 편집·복사·게시 링크 기록.
- 설정은 채널 탭을 기본으로 보여주고 `?tab=model` 등 필요한 설정으로 바로 이동 가능.
- 글감·초안·연결·발행·설정·문체의 주요 조회 실패에 복구 경로 추가.
- 보류·보관된 글감을 다시 볼 수 있는 필터와 복원 행동 제공.
- 기존 색상·로고·폰트와 서버 기능을 유지했다. 자동 게시, 별도 큐, 디자인 시스템 라이브러리는 추가하지 않았다.

## 검증과 한계

- 인메모리/DOM 회귀 테스트: 첫 행동 안내, 블로그만 연결한 수집, 부분 수집 실패, 오류 재시도, 근거 부족 상태 분류, 검색 초기화, 복사 없이 게시 링크 기록, 편집 중 갱신·저장 실패의 입력 보존, 저장 응답 즉시 반영, 클립보드 거부.
- Chrome에서 첫 방문·연결 후·목록·초안·오류·연결·발행 상태를 데스크톱과 모바일로 확인했다. 검색 초기화, 수집 실패, 수정·저장, 게시 링크 등록을 직접 조작했다. 외부 API는 mock으로 대체했다.
- `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `git diff --check`: 통과. 16개 테스트 파일의 66개 테스트 중 이번 사용 흐름 회귀 테스트는 9개다.
- Chrome 21개 화면 조합(7개 상태 × 데스크톱 밝은 테마·390px 모바일 밝은 테마·데스크톱 어두운 테마): 가로 넘침 0, 브라우저 실행 오류 0. [검사 결과](ux/browser-checks.json).
- axe-core의 WCAG 2 A/AA 및 2.1 AA 자동 검사: 해당 21개 화면에서 탐지된 위반 0. 초안 메뉴를 키보드로 열고 Escape로 닫았을 때 포커스 복귀도 확인했다. 자동 검사 통과는 전체 WCAG 준수나 스크린리더 사용성 검증을 의미하지 않는다.
- 인터뷰, 실제 게시물 품질 평가, 실사용 성공률 측정은 수행하지 않았다. 이 변경만으로 제품 시장 적합성이나 초안 품질이 검증되는 것은 아니다.
- 최초 개선에서는 추정 상태를 ‘작업 중’으로 오인시키지 않고 요청 접수와 결과를 구분했다. 이후 [생성 큐 개선](generation-queue.md)에서 영속적인 단계·오류·재시도와 진행 화면을 구현했다.
- 편집 보호는 서버 갱신, 링크 이동, 채널·언어 전환, 새로고침을 대상으로 한다. 브라우저 뒤로가기도 React Router 이동 차단으로 보호한다. 1440px·390px 실제 Chrome에서 수정 유지와 명시적 버리기 이동을 확인했다.

후속 사용성 검증은 ‘처음 접속한 사용자가 설명 없이 소스를 연결하고 첫 초안을 얻는가’,
‘초안을 수정한 뒤 게시 링크 기록까지 혼자 마칠 수 있는가’를 관찰하는 것이 우선이다.
첫 초안까지 걸리는 시간, 실패 후 재시도 성공, 편집 내용 손실 여부를 측정하고 다음 수정을 결정한다.


## 후속 개선: 설정 입력과 탐색

첫 개선 이후 설정 흐름을 추가 점검했다. 모델명·키·금지 표현을 입력한 상태에서 설정 SSE가 도착하면 입력이 초기화되고, 설정 탭은 URL의 변경이나 뒤로가기를 따라가지 않았다. 계정 내보내기·삭제 요청 실패에는 화면 안내도 없었다.

- [React의 상태 관리 지침](https://react.dev/learn/you-might-not-need-an-effect)에 따라 서버 데이터가 바뀔 때 모든 입력을 초기화하는 effect를 제거했다. 사용자가 편집한 값은 별도로 유지하고, 해당 항목 저장이 성공한 뒤에만 초기화한다. 키는 저장 성공 후 입력란에서 제거하며 브라우저 저장소에 보관하지 않는다.
- 저장 응답을 화면에 즉시 반영한다. SSE가 응답보다 먼저 도착하는 경우도 검사했다. 저장 중에는 입력을 잠그고 중복 요청을 방지하며, 실패하면 입력을 유지하고 재시도를 허용한다.
- 설정 탭을 검색 매개변수와 연결해 직접 링크·새로고침·뒤로가기에서 동일한 탭을 보여준다. 설정 내부 탭 이동으로 편집값을 잃지 않는다.
- 배경 조회 실패 시 기존 폼을 유지하고 재시도를 제공한다. 계정 내보내기·삭제 실패에도 오류를 표시한다. 삭제 검증은 모의 실패 응답만 사용했고 실제 계정은 삭제하지 않았다.
- 모바일 모델 입력을 한 열로 배치해 긴 모델명을 확인하기 쉽게 했다. 본문 링크의 밑줄, 언어 입력 라벨과 선택 상태를 보완했다.

[모바일 설정 화면](ux/after-settings-mobile.png) · [설정 브라우저 검사 결과](ux/settings-checks.json)

설정 회귀 테스트 7개를 추가했다. 전체 17개 파일의 테스트 73개와 린트·타입 검사·프로덕션 빌드가 통과했다. Chrome에서 다섯 탭 × 세 화면 조건(1440px 밝음·390px 밝음·1440px 어두움)의 15개 조합을 검사했다. 가로 넘침·실행 오류·해당 axe 자동 검사 위반은 모두 0이며, 뒤로가기 후 모델 입력 유지도 확인했다. 이 검증은 모의 API를 사용한다. 페이지를 완전히 떠나거나 새로고침한 뒤에도 설정 입력을 복구하는 기능은 포함하지 않는다.
