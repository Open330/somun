# 변경 보존과 한국어 품질 보완

긴 채널의 기본 생성 프롬프트에 변경 확인 목록을 추가하고 한국어 용어 지시를 보완했다. 최종 한국어 표본 2개에서 네 변경이 모두 언급되고 자동 검사가 통과했다. 검토한 표본에서 ‘정산’, ‘line endings’ 같은 표현은 사라졌지만 곧바로 게시 가능한 수준이라고 판정하지는 않았다.

## 로컬 코드 변경

- Show HN·Show GN·LinkedIn·블로그는 각 변경의 대상과 동작을 유지하고 배경·중복 문장부터 줄이도록 한다. 채널 글자 제한은 유지한다.
- X·Threads는 긴 변경 목록을 무리하게 모두 넣지 않고 제한 안에서 변경을 선택하도록 한다. 생략한 경우 전체 변경 목록인 것처럼 표현하지 않도록 지시한다.
- 한국어에는 줄바꿈, 의존성, 경로 구성 요소, 프록시 컨텍스트 매처 등 통용되는 표현을 제시한다. 식별자는 그대로 유지하고 모호한 동사는 의미를 추측해 번역하지 않도록 한다.
- 실험기에 optional requiredAny 개념별 동의어 검사를 추가했다. 이전 보고서와 사례 해시의 호환성도 검사한다.

운영 배포나 기본 모델 변경은 하지 않았다. 실제 호출은 실험 설정에서 지정한 Gemini 3.5 Flash Lite를 사용했다.

## 실험과 검사 기준의 변경

모든 실제 호출은 같은 공개 Vite 릴리스 자료를 사용했다. 총 14건이 생성됐다. 입력 자료 한 건에 대한 탐색이며 독립 보류 세트나 통계적 우열 검정이 아니다.

| 단계 | 생성 | 당시 자동 통과 | 관찰 |
|---|---:|---:|---|
| 단순 간결 지시 | 4/4 | 2/4 | 한국어에서 변경 누락·영어 혼용 |
| 전체 변경 보존 지시 | 4/4 | 2/4 | 변경은 보존했으나 ‘정산’ 1건, 번역 동의어 오탐 |
| 기본 프롬프트 확인 목록 | 4/4 | 3/4 | ‘프리로드’를 놓친 검사 오탐 1건, 한국어 용어 혼용 잔존 |
| 한국어 용어 지시까지 반영 | 2/2 | 2/2 | 네 변경 언급, 이번 표본에서 ‘정산’과 과도한 영어 구절 제거 |

첫 기준은 preload 문자열만 요구해 ‘미리 로드된’을 누락으로 판단했다. v2에서 동의어를 허용한 뒤에도 ‘프리로드’ 음역을 놓쳤다. v3에서 이를 추가했다. 원래 보고서와 점수는 그대로 보존했다.

v3로 **같은 출력을 사후 재검사**하면 각 단계 통과 수는 2/4, 3/4, 4/4, 2/2다. 이는 추가 생성이나 독립적인 검증 결과가 아니다. [재평가 JSON](reevaluation.json)에 당시 점수와 수정된 기준의 점수를 함께 기록했다. 동의어 추가로 해소된 실패는 생성 품질 개선으로 계산하지 않는다.

## 원문 검토와 남은 한계

‘settling’의 의미는 [Vite PR #23446](https://github.com/vitejs/vite/pull/23446)에서 확인했다. 설명과 코드 변경 맥락상 Promise 처리에 관한 표현이므로 재무적 의미의 ‘정산’으로 옮기는 것은 부적절하다. 입력 사실이 그 동작을 충분히 설명하지 않을 때에는 원문 동사를 보존하도록 했다. 이 PR의 상세 정보를 실험용 사실 블록에 추가하거나 제품의 자동 수집 범위를 넓히지는 않았다.

최종 두 결과는 CRLF 줄바꿈, node_modules 경로 처리, 프록시 매처 사전 컴파일, preload 의존성 처리를 모두 언급했다. 하나는 settling을 원문으로 유지했고 다른 하나는 ‘다시 처리하지 않도록’으로 풀었다. 후자의 상세 의미 정확성은 추가 원문 대조가 필요하다. 항목을 모두 언급했다는 것과 동작 의미를 완전히 검증했다는 것은 다르다.

‘무엇이 달라졌나.’라는 어색한 전환 문구와 영어 제목 설명은 남아 있다. 한 결과의 ‘버전을 공개했습니다’도 작성자의 역할에 따라 중립적인 표현으로 바꿀 필요가 있다. 게시 가능 여부·실제 수정 시간·사용자 선호는 평가하지 않았다. 위 내용 대조는 Codex(AI)의 검토이며 사람 평가로 집계하지 않는다.

## 검증·재현

- 전체 26개 파일의 테스트 136개, 린트·타입 검사·프로덕션 빌드가 통과했다.
- 긴/짧은 채널의 서로 다른 보존 규칙, 근거 없는 체크리스트 생성 방지, 한국어 지시 적용 범위, 동의어 허용과 실제 누락 탐지, 과거 보고서 해시 호환성을 검사한다.
- [지시 A/B 원본](instruction-ab-report.json), [확인 목록 원본](coverage-checklist-report.json), [한국어 최종 원본](korean-final-report.json)을 보존했다. 각 보고서에는 실행 당시 프롬프트가 들어 있다.

```sh
npm run experiment -- run --config experiments/coverage-korean.json --live --max-calls 2
npm test
```

현재 재실행은 현재 코드의 프롬프트를 사용한다. 과거 원본 프롬프트·검사 기준과 다른 경우 같은 실험의 독립 반복처럼 합산하지 않는다.
