# 추가 사용 흐름 점검과 수정

로컬 작업 트리에서 세 문제를 실제 Chromium과 SQLite로 재현하고 수정했다. 기준 커밋은 `0e80132da047e0e1ec630f985e9749c136e6e5d7`이며, JSON의 commit은 배포 버전이 아니라 수정 전 기준점이다.

## 1. 편집 중 새 버전 도착으로 저장 대상이 바뀜 — 우선도 높음

재현: v1에서 재작성 요청 → 생성 대기 중 v1 편집 → v2 생성 완료 → 변경 저장.

수정 전: v1은 그대로이고 v2 본문이 v1의 편집 내용으로 덮였다. 화면에 입력을 유지하는 처리와 저장 대상 ID를 선택하는 처리가 분리돼 있었기 때문이다.

수정 후: 편집 시작 시의 버전을 유지하고 그 버전에 저장한다. 새 버전 도착을 안내하며, 저장 후에도 수정한 버전을 보여준다. 편집 중 버전 선택은 잠근다. SQLite에서 v1에만 수정이 반영되고 v2 생성 본문은 보존되는 것을 확인했다.

증거: [수정 전 데이터 검사](audit_edit.json), [수정 후 검사](verified/audit_edit.json), [수정 후 화면](verified/audit_edit-preserved-version.png).

## 2. 게시 직후 링크를 고쳐도 이전 링크가 표시됨 — 우선도 중간

재현: 게시 링크 기록 → 같은 화면에서 링크 고치기 → 새 주소 저장.

수정 전: DB와 상세 API에는 새 주소가 있지만 게시 완료 카드의 로컬 상태가 이전 주소를 우선 표시했다. 전체 새로고침을 해야 일치했다.

수정 후: 링크 수정 결과를 즉시 화면에 반영하고 서버 조회와 일치하면 임시 상태를 해제한다. 새로고침 전후 모두 수정한 주소가 표시되는 것을 확인했다.

증거: [수정 전](audit_link.json), [수정 후](verified/audit_link.json), [화면](verified/audit_link-corrected-link.png).

## 3. 발행 기록에서 다른 초안이 열림 — 우선도 중간

재현: 영어 초안 게시 기록과 미게시 한국어 초안이 있는 글감 → 발행 기록의 제목 클릭.

수정 전: 일반 검토 진입의 미게시 우선 선택이 적용돼 한국어가 열렸다.

수정 후: 발행 기록 링크가 초안 ID를 전달한다. 해당 채널·언어와 버전을 선택해 게시 기록을 열고, ‘초안 다시 보기’에서도 그 버전을 보여준다. 검증 조건을 확장해 같은 언어에 더 최신 미게시 버전이 있어도 올바른 이전 게시 버전이 선택되는지 확인했다. 초안 ID가 없는 기존 기록은 일반 글감 링크를 유지한다.

증거: [수정 전](audit_published.json), [수정 후](verified/audit_published.json), [화면](verified/audit_published-correct-target.png).

## 검증과 재실행

전체 자동 테스트 380개 통과. 타입 검사·린트·프로덕션 빌드 통과. 기존 페르소나 15단계와 새 재현 시나리오 3개를 실행했다. 마지막 저장 후 버전 표시 보완은 관련 화면 테스트와 해당 브라우저 시나리오를 다시 실행해 확인했다.

```sh
npm run build
node scripts/persona-review.mjs
node scripts/persona-review.mjs audit_link
node scripts/persona-review.mjs audit_edit
node scripts/persona-review.mjs audit_published
```

현재 실행기는 수정된 기대 동작을 검사하고 `verified/`에 저장한다. 이 폴더 상위의 최초 audit JSON에서 pass는 **결함을 재현하는 검사**가 성공했다는 뜻이다.

외부 AI와 SNS는 호출하지 않았다. 생성 응답은 모의 데이터다. 이번 검증은 서로 다른 버전 사이의 덮어쓰기를 대상으로 하며, 여러 탭에서 같은 버전을 동시에 편집하는 충돌까지 해결했다고 주장하지 않는다. 변경은 로컬 작업 트리에 있고 머지·배포 전이다.
